# Agent 功能规格

## 一、任务边界清单

### 1. Agent 核心职责

Agent 的核心职责是帮助用户围绕新闻话题、热点事件、公开信息和长期关注主题进行查询、整理、追踪和本地记忆维护。

Agent 应支持：

- 联网搜索公开网页信息。
- 总结某一新闻话题或热点事件的最新进展。
- 对已长期关注的话题进行本地 Markdown 记忆召回。
- 在满足条件时创建或更新本地话题 Markdown 文件。
- 将联网搜索结果与本地已有时间线合并，形成持续更新的结构化记忆。

### 2. Agent 可以处理的任务

- 查询某个话题的最新进展。
- 查询某个人物、公司、政策、公共事件的近期动态。
- 总结联网搜索结果。
- 对用户明确要求关注的话题建立本地 Markdown 记录。
- 对本地已有关注话题进行继续追踪和更新。
- 读取本地话题摘要，用于判断用户本次输入是否命中已有关注话题。
- 读取本地话题详情，用于合并旧内容和新内容。

### 3. Agent 不应处理的任务

- 用户未要求长期关注，且本地也没有命中已有关注话题时，不应创建 Markdown 文件。
- 用户只是普通查询、了解、分析、总结时，不应写入本地记忆。
- 不应把临时闲聊内容写入 Markdown 话题文件。
- 不应把不确定、无来源、无时间的信息直接写入时间线。
- 不应在 `topic_markdown_store` 参数中使用 `{ "...": null }` 等省略占位内容。
- 不应把工具调用结果伪装成最终事实，应结合来源和摘要进行整理。
- 不应为了回答普通问题而强制读取本地 Markdown 详情。

### 4. Markdown 记忆触发条件

允许创建或更新 Markdown 文件的条件只有两类：

- 用户明确表达长期关注意图，例如“帮我关注”“持续关注”“保持跟踪”“记录一下”“保存到本地”“维护时间线”。
- 用户虽然没有明确说关注，但本次输入命中了 `data/topics` 下已经存储的 Markdown 关注话题，例如“上次关注的内存条价格怎么样了”。

如果不满足以上任一条件，Agent 只能在本次会话内回答，不应调用 `topic_markdown_store`。

## 二、任务路径

### 路径 A：普通联网查询

适用输入：

- “查一下韩红最近新闻”
- “总结一下内存条最近价格走势”
- “最近 AI 裁员有什么新消息”

预期路径：

1. 判断用户是普通查询，没有明确长期关注意图。
2. 如需最新信息，调用 `doubao_search`。
3. 根据搜索结果整理结构化回答。
4. 不调用 `topic_markdown_store`。

允许调用：

- `doubao_search`
- 必要时可调用 `topic_markdown_read_summary` 判断是否命中已有关注话题。

禁止调用：

- 未命中已有关注话题且用户无关注意图时，禁止调用 `topic_markdown_store`。

### 路径 B：新话题长期关注

适用输入：

- “帮我关注一下内存条最近价格走势”
- “持续关注韩红近期舆论事件”
- “记录一下互联网大厂因 AI 裁员这个话题”

预期路径：

1. 判断用户明确要求长期关注。
2. 调用 `doubao_search` 获取最新信息。
3. 调用 `topic_markdown_read_summary` 判断是否已有相关本地话题。
4. 如果没有相关话题，整理搜索结果为新话题结构。
5. 调用 `topic_markdown_store`，使用 `operation=create` 或 `operation=auto` 创建 Markdown。
6. 最终回答用户已创建或已开始关注，并返回核心摘要。

必须保证：

- `topic_name` 是具体话题名称。
- `keywords` 是话题关键词。
- `summary` 是话题整体摘要。
- `timeline_items` 是具体条目，不允许省略。
- 时间线条目应包含 `date/title/source/url/summary`。

### 路径 C：已有话题继续关注

适用输入：

- “上次关注的内存条价格怎么样了”
- “之前那个 AI 裁员话题有新进展吗”
- “更新一下韩红近期热点”

预期路径：

1. 调用 `topic_markdown_read_summary` 读取本地话题摘要。
2. 判断本次输入是否命中已有关注话题。
3. 命中后调用 `topic_markdown_read_detail` 读取完整 Markdown。
4. 调用 `doubao_search` 获取最新联网内容。
5. 结合本地旧内容和联网新内容，提炼新增或更新条目。
6. 调用 `topic_markdown_store`，使用 `operation=update` 更新 Markdown。
7. 最终回答用户更新结果、关键变化和文件路径。

必须保证：

- 不重复写入已有时间线条目。
- 新旧内容合并后保持时间倒序。
- 来源字段优先取 `site_name` 或 `raw.SiteName`。
- 链接字段优先取 `url` 或 `raw.Url`。

### 路径 D：已有话题命中但不需要联网

适用输入：

- “上次关注的内存条价格记录里有什么”
- “看看之前保存的韩红话题摘要”

预期路径：

1. 调用 `topic_markdown_read_summary` 判断相关话题。
2. 命中后调用 `topic_markdown_read_detail`。
3. 根据本地 Markdown 内容回答用户。
4. 不调用 `doubao_search`，除非用户要求最新信息。
5. 不调用 `topic_markdown_store`，除非用户要求更新。

## 三、约束规则

### 1. 工具选择规则

- 有联网查询意图时，优先使用 `doubao_search`。
- 有本地话题召回需求时，使用 `topic_markdown_read_summary`。
- 已确定相关本地话题并需要读取完整内容时，使用 `topic_markdown_read_detail`。
- 只有需要创建或更新 Markdown 话题记忆时，使用 `topic_markdown_store`。

### 2. Markdown 写入规则

- 普通查询不得写入 Markdown。
- 未命中本地已有关注话题且用户无关注意图，不得写入 Markdown。
- 写入前必须整理出明确、具体、可读的结构化内容。
- 不得把搜索结果中大量原始正文无筛选地写入 Markdown。
- 不得把 `{ "...": null }`、`省略`、`同上`、`若干结果` 等占位内容写入 Markdown。
- 时间线必须按时间倒序排列。
- 时间线不得包含“备注”字段。
- 来源字段不得为空，优先取搜索结果的 `site_name`。
- 链接字段不得为空，优先取搜索结果的 `url`。

### 3. 输出规则

- 最终回答必须是结构化数据。
- 如果执行了工具调用，应总结工具调用结果，而不是只返回工具原始响应。
- 如果创建或更新了 Markdown，应返回文件路径、操作类型、追加条目数和话题摘要。
- 如果没有写入 Markdown，应明确本次只是查询回答。

### 4. 时间规则

- “最近”“近期”等模糊时间默认解释为最近 2 个月。
- 涉及最新进展时，应优先使用联网搜索结果。
- 写入时间线时，应优先使用搜索结果中的发布时间。

### 5. 本地记忆匹配规则

- 用户出现“上次”“之前”“关注的”“那个话题”“怎么样了”“有更新吗”等指代表达时，应优先调用 `topic_markdown_read_summary`。
- 匹配应综合标题、关键词、摘要判断，不只看用户输入关键词。
- 如果摘要匹配结果不确定，应优先读取候选详情后再判断。
- 不应因为用户没有说“关注”就忽略已存储话题。
