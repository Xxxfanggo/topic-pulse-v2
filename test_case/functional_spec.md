# Agent 功能规格

## 1. 任务边界

### 1.1 核心职责

Topic Pulse Agent 的核心职责是围绕新闻话题、热点事件、公开信息和用户长期关注主题，完成检索、整理、追踪和本地 Markdown 记忆维护。

Agent 应支持：

- 联网搜索公开网页信息。
- 总结某个新闻话题、人物、公司、行业、政策或热点事件的最新进展。
- 召回 `data/topics` 下已经长期关注的 Markdown 话题。
- 在满足条件时创建或更新本地话题 Markdown。
- 将联网搜索结果与本地旧记忆合并，形成持续更新的时间线。
- 在最终回答中返回 Web 页面可展示的引用资料和新旧信息标识。

### 1.2 可处理任务

- 普通联网查询：例如“查一下内存条最近价格走势”。
- 最新进展总结：例如“韩红最近有什么热点新闻”。
- 新话题关注：例如“帮我持续关注互联网大厂因 AI 裁员这个话题”。
- 已关注话题更新：例如“上次关注的内存条价格怎么样了”。
- 已关注话题历史查询：例如“看看之前保存的韩红话题摘要”。
- 多轮对话中的指代理解：例如“这个话题继续跟一下”。

### 1.3 不应处理或不应自动执行的任务

- 用户只是普通查询，且没有命中本地已关注话题时，不应创建 Markdown。
- 用户没有明确保存/关注意图时，不应把临时查询写入本地记忆。
- 不应把闲聊内容、无来源内容、不确定信息写入话题时间线。
- 不应把 `{ "...": null }`、省略号、占位符、空壳条目写入 Markdown。
- 不应直接删除或清空本地 Markdown 文件，除非未来实现了明确的删除工具和确认机制。
- 不应把大段工具原始响应原样作为最终回答。
- 不应把搜索结果里的 `content/raw/logo_url` 等大字段原样塞回下一轮 LLM 上下文。

## 2. 工具职责

### 2.1 `doubao_search`

用于联网查询任何用户想了解的最新话题内容。

必须使用场景：

- 用户明确要求查找、搜索、看看最新进展。
- 问题涉及新闻、价格、政策、人物动态、公司动态、行业走势等可能变化的信息。
- 已关注话题需要更新最新内容。

参数要求：

- 必须包含 `query`。
- `query` 应补全模糊时间范围，例如“最近”默认转为“最近 6 个月”。

进入 LLM 上下文时的压缩要求：

- 只保留查询词、结果数量、前若干条标题、站点、链接、发布时间、摘要。
- 不携带全文 `content`、原始 `raw`、图片链接、评分等大字段。

### 2.2 `topic_markdown_read_summary`

用于读取本地已关注话题的标题、关键词、基本信息和摘要，帮助 Agent 判断用户本次输入是否命中已有话题。

必须使用场景：

- 用户提到“上次”“之前”“关注过”“那个话题”“怎么样了”“更新一下”等指代。
- 用户输入可能命中本地已关注话题。
- 用户明确要求持续关注一个话题，写入前需要判断是否已有相关文件。

### 2.3 `topic_markdown_read_detail`

用于读取某一个 Markdown 话题的完整内容。

必须使用场景：

- `topic_markdown_read_summary` 返回了相关候选，且需要基于旧内容回答或更新。
- 已关注话题需要与最新搜索结果合并。

限制：

- 不应在没有候选或用户只是普通查询时强行读取详情。
- 多个候选不确定时，应优先澄清或谨慎处理，不能随意更新其中一个。

### 2.4 `topic_markdown_store`

用于创建或更新本地话题 Markdown。

允许使用场景只有两类：

- 用户明确表达长期关注、保存、记录、维护时间线等意图。
- 用户本次输入命中了本地已关注话题，需要更新该话题。

禁止使用场景：

- 普通查询没有命中已关注话题。
- 用户明确说“不保存”“不要记录到本地”。
- 只是读取历史摘要，不需要更新。

参数要求：

- 必须包含 `topic_name`、`summary`。
- 创建或更新时必须提供 `timeline_items` 或可提炼出时间线的 `latest_content`。
- 时间线条目应包含 `date/title/source/url/summary`。
- `source` 优先取 `site_name` 或 `raw.SiteName`。
- `url` 优先取 `url` 或 `raw.Url`。

## 3. 任务路径

### 路径 A：普通联网查询

适用输入：

- “查一下内存条最近价格走势”
- “韩红最近有什么新闻”
- “最近 AI 裁员有什么新消息”

预期流程：

1. 判断为普通查询。
2. 调用 `doubao_search`。
3. 必要时调用 `topic_markdown_read_summary` 判断是否命中已有关注话题。
4. 如果没有命中已关注话题，直接回答，不调用 `topic_markdown_store`。
5. 最终回答包含 `query_key` 和 `reference_data`。

### 路径 B：新话题长期关注

适用输入：

- “帮我关注一下内存条最近价格走势”
- “持续关注韩红近期争议事件”
- “记录一下互联网大厂因 AI 裁员这个话题”

预期流程：

1. 判断用户有明确长期关注意图。
2. 调用 `topic_markdown_read_summary` 判断是否已有相关话题。
3. 调用 `doubao_search` 获取最新信息。
4. 如果没有相关话题，整理为新话题结构。
5. 调用 `topic_markdown_store` 创建 Markdown。
6. 最终回答包含 `query_key`、`reference_data`、`topic_update`。

### 路径 C：已关注话题更新

适用输入：

- “上次关注的内存条价格怎么样了”
- “之前那个 AI 裁员话题有新进展吗”
- “更新一下韩红近期热点”

预期流程：

1. 调用 `topic_markdown_read_summary`。
2. 命中已关注话题后，调用 `topic_markdown_read_detail`。
3. 调用 `doubao_search` 获取最新内容。
4. 综合旧 Markdown 和搜索结果，提炼新增/已有信息。
5. 调用 `topic_markdown_store` 更新 Markdown。
6. 最终回答必须清楚标识“新增信息”和“已记录信息”。

### 路径 D：已关注话题历史查询

适用输入：

- “看看之前保存的韩红话题摘要”
- “上次关注的内存条价格记录里有什么”

预期流程：

1. 调用 `topic_markdown_read_summary`。
2. 命中后调用 `topic_markdown_read_detail`。
3. 基于本地 Markdown 回答。
4. 不调用 `doubao_search`，除非用户要求最新信息。
5. 不调用 `topic_markdown_store`，除非用户要求更新。

## 4. 约束规则

### 4.1 Markdown 记忆规则

- 普通查询不写入 Markdown。
- 命中已关注话题时，即使用户没有再次说“持续关注”，也应进入已关注话题逻辑。
- 写入前必须提炼结构化内容，不能原样写入大段搜索结果。
- 时间线必须按时间倒序排列。
- 时间线不包含“备注”字段。
- 时间线应尽量保证来源和链接非空。
- 重复 URL 或高度重复标题不应重复写入。

### 4.2 最终回答规则

最终回答应为结构化 JSON 字符串，并能被 Web 层解析。

如果调用过 `doubao_search`，必须包含：

- `query_key`：实际查询关键词。
- `reference_data`：参考资料数组，每项包含 `title` 和 `url`。

如果调用过 `topic_markdown_store`，必须包含：

- `topic_update.topic_name`
- `topic_update.status`
- `topic_update.new_count`
- `topic_update.existing_count`
- `topic_update.new_items`
- `topic_update.existing_items`

### 4.3 多轮会话规则

- 历史对话由 session 层统一管理，不应由 Web 或 CLI 各自拼接。
- 每次调用 `ReActAgent.run()` 时，应能通过 `session_id` 获取历史上下文。
- 历史上下文只用于理解指代关系，不代表最新事实。
- 涉及最新事实时仍应优先联网搜索。

### 4.4 可观测规则

trace 日志必须能观测：

- 每次 LLM 调用的输入 messages。
- 每次 LLM 调用的响应。
- 每次工具调用的名称、参数、响应、耗时、成功状态。
- Agent 是否正常结束。

稳定性要求：

- trace 可以记录完整工具响应。
- 进入下一轮 LLM 的工具 observation 必须压缩，避免上下文过大导致流程中断。
